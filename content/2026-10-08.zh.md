## Selected Items

## Local sandboxing for GitHub Copilot now generally available
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/

GitHub 宣布 Copilot 本地沙箱正式 GA，覆盖 Copilot CLI、Copilot app，以及 VS Code 中使用 Agent Host 的会话。沙箱基于 Microsoft eXecution Container（MXC），可将统一策略映射到 Windows、macOS、Linux 的原生系统控制上，限制 agent 触发的工具与命令对文件系统、网络、凭据及其他系统能力的访问。

Why it matters: 这是 AI 编码代理从个人实验走向企业级落地的关键基础设施。真正阻碍 agent 大规模进入开发流程的，不是模型能力本身，而是执行边界、凭据暴露面、网络访问和组织可控性。GitHub 现在给出了统一且可强制执行的本地执行隔离层，使组织可以在不完全信任代理的前提下逐步放开更高自治度的工作流。

Key takeaways:
- 沙箱策略与模型选择解耦：无论 Copilot 使用哪种模型，工具执行都可被同一套策略约束。
- 企业可通过托管设置强制开启沙箱并禁止开发者弱化策略，这对平台治理与合规落地非常关键。

Tags: agent-safety, sandboxing, copilot, enterprise-governance, developer-tooling
Scores: signal 10/5, novelty 8/5, actionability 9/5

## Purpose-built model for leaked secret detection
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-purpose-built-model-for-leaked-secret-detection/

GitHub 发布用于泄露密钥检测的专用模型，强调其为上下文感知的检测模型，而不是生成代码或文本的通用模型。该模型可根据周围代码识别可能的凭据，包括没有固定 token 格式的密码，并将逐步扩展到 secret scanning alerts、push protection，以及 Copilot CLI / Copilot app 的 /security-review 工作流。

Why it matters: 这代表安全能力开始适配 AI coding 时代的新泄露面：不仅要扫描已知格式的密钥，还要识别代理生成、重构或复制粘贴过程中出现的非标准凭据。更重要的是，GitHub 把该能力嵌入提交前、扫描中、以及 agent 驱动的安全审查里，说明未来安全检测会从事后扫描转向开发流程内联化。

Key takeaways:
- 检测面正在从静态模式匹配扩展到基于代码上下文的专用模型判断，适合识别非标准密码和隐式凭据。
- 同一能力将贯穿扫描告警、push protection 与 Copilot security review，表明安全与 AI 开发体验正在深度融合。

Tags: secret-scanning, application-security, ai-detection, copilot, secure-by-default
Scores: signal 9/5, novelty 8/5, actionability 8/5

## Discover local models in GitHub Copilot CLI
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/

GitHub Copilot CLI 现在可通过 /model 直接发现运行中的本地 Ollama 模型，并与现有配置模型、GitHub 提供的云模型一起展示。用户可在当前会话内添加并切换模型，无需重启 CLI；系统还会显示 provider、endpoint 与连接失败原因。GitHub 同时明确：选择本地模型不等于默认离线，离线模式需显式配置。

Why it matters: 这不是简单的“支持本地模型”，而是把本地模型纳入统一的代理工具链控制面。对平台团队来说，关键意义在于：模型选择、工具调用、provider 管理、离线语义和遥测边界开始被产品化。它预示未来开发环境将默认支持混合模型路由，而不是单一云端模型。

Key takeaways:
- 本地模型与云模型开始在同一 CLI 交互面中被统一管理，这是多模型开发工作流的重要信号。
- GitHub 特别澄清了“本地 ≠ 离线”，说明数据流、网络流和工具执行边界需要被显式治理，而不能靠部署位置想当然推断。

Tags: local-models, ollama, copilot-cli, model-routing, developer-tooling
Scores: signal 8/5, novelty 7/5, actionability 8/5

## Claude Haiku 5.5 in GitHub Copilot
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-claude-haiku-5-5-in-github-copilot/

Anthropic 的 Claude Haiku 5.5 已在 GitHub Copilot 中正式可用，面向高频低延迟场景，如 subagents、快速编辑和终端任务。GitHub 表示早期测试中，它在许多编码任务上可达到 Claude Sonnet 5 的效果，同时消耗更少 token 和步骤，并可由企业管理员通过模型策略控制启用。

Why it matters: 该更新的核心价值不在“又多了一个模型”，而在于 Copilot 正按任务类型做模型分层：把低成本、低延迟模型用于高频代理子任务。这会直接影响企业的 AI 成本结构与默认编排策略，尤其是在 agent 工作流把一次用户请求拆成多个子调用时。

Key takeaways:
- GitHub 明确把 Haiku 5.5 定位到 subagents、终端和快速编辑，说明代理系统正在按任务粒度优化模型选择。
- 如果轻量模型在大量编码任务上逼近更强模型效果，企业将更倾向采用分层路由而非统一默认大模型。
