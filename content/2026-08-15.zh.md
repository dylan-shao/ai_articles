## Multiple redirect URIs and token refresh for OAuth apps - GitHub Changelog
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-08-14
- URL: https://github.blog/changelog/2026-08-14-multiple-redirect-uris-and-token-refresh-for-oauth-apps/

GitHub 为 OAuth Apps 和 GitHub Apps 推出了多项认证与重定向安全增强：OAuth 应用可启用 8 小时有效的短期 access token 与 6 个月 refresh token；OAuth 应用支持多个 redirect URI；GitHub Apps 与 OAuth Apps 均可按需启用 redirect URI 通配匹配。新应用默认启用短期令牌模式，也可通过 offline_access scope 渐进式接入刷新流程。

Why it matters: 对构建 AI 编码代理、CLI、IDE 扩展、内部开发者门户和多环境集成平台的团队来说，这不是普通安全公告，而是认证架构层面的变更。过去很多开发者工具依赖长期 token、单一回调 URI 或手工例外配置；现在 GitHub 官方能力更适合支持本地开发、预览环境、云端 agent、桌面客户端与企业网关等多入口场景，同时降低长期凭证泄露风险。

Key takeaways:
- GitHub 正在把 OAuth 集成默认推向短期 access token + refresh token 模式，说明开发者工具生态将逐步告别长期静态令牌。
- 多个 redirect URI 与通配匹配显著降低多环境、多客户端和 agent 场景下的集成摩擦，但也要求团队重新审视 redirect 白名单与回调安全边界。
