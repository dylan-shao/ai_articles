## Content exclusions generally available in Copilot app and CLI - GitHub Changelog
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-09-02
- URL: https://github.blog/changelog/2026-09-02-content-exclusions-generally-available-in-copilot-app-and-cli/

GitHub 宣布 Copilot App 与 Copilot CLI 正式支持企业、组织和仓库级别配置的内容排除策略。被排除的文件不会被 Copilot 作为上下文使用，从而在代理式工作流中减少敏感代码泄露风险。

Why it matters: 这不是新能力原型，而是治理能力落到 App 和 CLI 两个高风险入口，意味着企业终于可以把现有的代码隔离策略延伸到代理式开发链路。对于平台团队来说，这直接影响是否能在终端和多仓场景中放心放开 AI 编码权限。

Key takeaways:
- 内容排除策略已从管理面扩展到 Copilot App 和 CLI 的实际上下文检索路径。
- 其核心价值在于为代理式工作流建立更明确的敏感代码边界，而不是提升模型能力本身。

Tags: Copilot, Enterprise Governance, CLI, Security, Context Control

## Enterprise-managed settings support any default model - GitHub Changelog
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-09-02
- URL: https://github.blog/changelog/2026-09-02-enterprise-managed-settings-support-any-default-model/

GitHub 现在允许企业通过托管设置为新会话指定任意 Copilot 默认模型，并可按团队定制不同默认值。管理员还可以将该配置设为可覆盖，让团队在企业基线之上选择自己的默认模型。

Why it matters: 随着编码助手进入多模型时代，真正的运营难点不再是‘有没有模型’，而是‘谁默认用什么模型、在哪些团队可覆盖、如何形成可审计基线’。这项更新说明模型治理正在从个人偏好转向企业级策略编排。

Key takeaways:
- 企业现在可以把默认模型选择纳入统一治理，并按团队映射差异化策略。
- “可覆盖默认值”机制适合在统一合规基线和团队自主优化之间做平衡。

Tags: Copilot, Model Governance, Enterprise, Developer Tooling, Policy
Scores: signal 6/5, novelty 5/5, actionability 7/5
