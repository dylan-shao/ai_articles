## Introducing Agentic Batch Changes: the frontier agent for code change at scale
- Source: Sourcegraph Blog
- Author: Lauren Preston
- Publish date: 2026-09-14
- URL: https://sourcegraph.com/blog/introducing-agentic-batch-changes

Sourcegraph introduced Agentic Batch Changes, evolving its Batch Changes system from a scripted bulk-change engine into an agentic system for executing migrations across hundreds or thousands of repositories. It targets org-wide migrations such as .NET upgrades, deprecated API replacements, and CI standardization, aiming to let a single engineer drive and track large-scale codebase changes through PRs.

Why it matters: The high signal here is not “another coding agent,” but the move from single-repo assistance to org-scale change orchestration and convergence. For backend and platform leaders, the expensive problem is rarely writing one fix; it is rolling that fix safely across heterogeneous repos with config drift and implementation variance. If Agentic Batch Changes can reliably adapt to repo-level differences, generate reviewable PRs, and track migration completion, it becomes a meaningful execution layer for tech-debt cleanup, runtime upgrades, policy rollout, and security remediation.

Key takeaways:
- The value center of AI coding is shifting from code generation to cross-repo migration execution and closed-loop tracking.
- Critical capabilities for large-codebase governance are repo understanding, variance adaptation, PR orchestration, and completion observability, not just model quality.
- If mature, this class of system can materially change how platform teams handle framework upgrades, deprecated APIs, CI/CD standardization, and security remediations.

## Configure cost and quality in Copilot auto model selection
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-09-14
- URL: https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/

GitHub added three preference tiers to Copilot auto model selection—efficiency, balance, and intelligence—to let users steer tradeoffs among cost, quality, and latency. The system still selects models per prompt, and billing depends on the actual model chosen.

Why it matters: This update is light on technical detail, but it signals that AI coding tools are moving from a single default model toward explicit inference-budget governance. For engineering leaders, that implies IDE- and CLI-level agent usage will increasingly resemble cloud resource management, with distinct cost caps, latency targets, and quality thresholds for different task types.

Key takeaways:
- Auto model selection is beginning to expose cost/quality/latency policy, showing AI coding is entering a more governable phase.
- Even under the “intelligence” tier, simple tasks may still route to smaller models, indicating prompt-level routing is becoming the default architecture.
