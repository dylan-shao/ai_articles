## Multiple redirect URIs and token refresh for OAuth apps - GitHub Changelog
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-08-14
- URL: https://github.blog/changelog/2026-08-14-multiple-redirect-uris-and-token-refresh-for-oauth-apps/

GitHub introduced several authentication and redirect security upgrades for OAuth Apps and GitHub Apps: OAuth apps can opt into 8-hour short-lived access tokens with 6-month refresh tokens; OAuth apps now support multiple redirect URIs; and both GitHub Apps and OAuth Apps can enable wildcard redirect matching when needed. New apps default to short-lived tokens, and developers can roll out refresh support gradually via the offline_access scope.

Why it matters: For teams building AI coding agents, CLIs, IDE extensions, internal developer portals, and multi-environment integrations, this is more than a routine security note—it changes auth architecture assumptions. Many developer tools historically relied on long-lived tokens, a single callback URI, or ad hoc exceptions; GitHub now provides first-class support for local development, preview environments, cloud agents, desktop clients, and enterprise gateways while reducing long-lived credential exposure.

Key takeaways:
- GitHub is pushing OAuth integrations toward a default model of short-lived access tokens plus refresh tokens, signaling a broader move away from long-lived static tokens in developer tooling.
- Multiple redirect URIs and wildcard matching reduce integration friction across multi-environment, multi-client, and agent-based setups, but teams must re-evaluate redirect allowlists and callback security boundaries.
