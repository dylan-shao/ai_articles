## Update your IDE to restore agent activity in Copilot usage metrics
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-06
- URL: https://github.blog/changelog/2026-10-06-update-your-ide-to-restore-agent-activity-in-copilot-usage-metrics/

GitHub disclosed that drops in Copilot agent activity and agent lines-of-code metrics were caused by an attribution issue: after some IDEs moved agent-mode sessions onto the Copilot SDK, those sessions stopped identifying their source IDE, so dashboards and APIs could not attribute them correctly. Some usage was even counted as Copilot CLI activity. A fix is available in VS Code and will roll out to other IDEs, but activity lost before the upgrade cannot be recovered.

Why it matters: This matters because it exposes a fragile layer in enterprise AI-coding adoption: measurement infrastructure. Many teams use agent activity, lines-of-code, active-user counts, and tool mix to justify rollout, budget seats, and assess enablement. If SDK and IDE version changes can distort those numbers, conclusions about declining adoption or weak ROI may be wrong. For platform teams, that is more urgent than a feature announcement.

Key takeaways:
- When agent sessions moved to the Copilot SDK without preserving IDE identity, Copilot usage dashboards and APIs undercounted agent activity.
- The fix depends on developers upgrading to specific IDE versions, and missed historical activity cannot be backfilled, so enterprises need IDE version governance as part of AI tooling measurement.
