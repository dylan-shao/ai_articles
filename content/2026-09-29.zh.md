## Claude Sonnet 5.5 in GitHub Copilot
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-09-28
- URL: https://github.blog/changelog/2026-09-28-claude-sonnet-5-5-in-github-copilot/

GitHub 宣布 Claude Sonnet 5.5 已在 GitHub Copilot 中正式可用，覆盖 VS Code、Visual Studio、JetBrains、Copilot CLI、Copilot coding agent、GitHub App 等多个入口。公告称其在早期测试中，与 Sonnet 5 相比可在编码任务上以更少的步骤、tokens 和工具调用完成工作，并且完成速度更快；企业与商业版管理员可通过模型策略控制是否启用该模型。

Why it matters: 尽管这不是一篇技术深文，但它说明 AI 编码平台竞争正从“谁有模型”转向“同一工作流下的多模型编排、成本/延迟优化和管理员治理”。对平台负责人而言，更关键的信息不是模型名本身，而是 Copilot 已把模型选择、策略控制和 usage-based billing 进一步产品化，意味着团队需要开始管理模型路由、预算和合规边界。

Key takeaways:
- GitHub 正在强化 Copilot 的多模型能力，并把模型选择扩展到 IDE、CLI、移动端与 coding agent 等统一入口。
- 公告强调 Sonnet 5.5 的效率优势——更少步骤、tokens 与工具调用——表明供应商开始把 agent 成本与延迟作为一等优化目标。
- 企业管理员可以通过 model policy 控制启用范围，说明模型治理已经成为企业级 AI 编码产品的标准能力。

## Implications

- 团队应开始比较不同模型在真实代码库任务上的单位成本、完成时间和工具调用次数，而不只看主观编码质量。
- 平台/开发效能团队需要建立模型准入与默认路由策略，避免多模型并存后产生不可控成本与合规风险。
- 如果你在评估 AI coding agent，下一步应优先设计内部 harness，以量化 token、工具调用、成功率和迭代次数。
