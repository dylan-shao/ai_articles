## Local sandboxing for GitHub Copilot now generally available
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/

GitHub announced GA for local sandboxing in Copilot across Copilot CLI, the Copilot app, and VS Code sessions using Agent Host. It is powered by Microsoft eXecution Container (MXC), which maps a common policy model to native OS controls on Windows, macOS, and Linux to restrict agent-triggered tools and commands across filesystem, network, credentials, and other capabilities.

Why it matters: This is core infrastructure for moving AI coding agents from individual experimentation to enterprise deployment. The real blocker to wider agent adoption is not model quality alone, but execution boundaries, credential exposure, network access, and organizational control. GitHub now provides a unified, enforceable local isolation layer so teams can allow more autonomous workflows without fully trusting the agent.

Key takeaways:
- Sandbox policy is decoupled from model choice: the same execution controls apply regardless of which model Copilot uses.
- Enterprises can require sandboxing and enforce non-weakenable policies through managed settings, which is critical for governance and compliance.

## Purpose-built model for leaked secret detection
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-purpose-built-model-for-leaked-secret-detection/

GitHub introduced a purpose-built model for leaked-secret detection, emphasizing that it is a context-aware detection model rather than a general code/prose generator. It reads surrounding code to identify likely credentials, including passwords without recognizable token formats, and is being extended across secret scanning alerts, push protection, and Copilot CLI / Copilot app via /security-review workflows.

Why it matters: This reflects how security controls are adapting to AI coding-era leakage patterns: not just matching known token formats, but detecting non-standard credentials introduced through agent generation, refactoring, or copy/paste. More importantly, GitHub is embedding the capability before commit, during scanning, and inside agent-driven security review, signaling a shift from post-hoc scanning to in-flow security controls.

Key takeaways:
- Detection is expanding beyond static pattern matching into code-context-aware model inference, which is better suited for non-standard passwords and implicit credentials.
- The same capability is being threaded through alerts, push protection, and Copilot security review, showing deep convergence between security workflows and AI-assisted development.

Tags: secret-scanning, application-security, ai-detection, copilot, secure-by-default
Scores: signal 9/5, novelty 8/5, actionability 8/5

## Discover local models in GitHub Copilot CLI
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/

GitHub Copilot CLI now lets users discover supported local Ollama models via /model, alongside configured models and GitHub-hosted cloud models. Users can add and switch models within the current session without restarting the CLI, while also seeing provider, endpoint, and connection-failure details. GitHub also makes it explicit that choosing a local model does not automatically mean offline mode.

Why it matters: This is more than 'supporting local models'—it folds local models into a unified agent tooling control plane. For platform teams, the key significance is that model choice, tool calling, provider management, offline semantics, and telemetry boundaries are becoming first-class product concepts. It points toward hybrid model routing as the default developer experience rather than a single hosted model.

Key takeaways:
- Local and cloud models are now managed through the same CLI interaction surface, which is an important signal for multi-model developer workflows.
- GitHub explicitly clarifies that 'local' does not equal 'offline,' underscoring that data flow, network flow, and tool-execution boundaries must be governed explicitly.

Tags: local-models, ollama, copilot-cli, model-routing, developer-tooling
Scores: signal 8/5, novelty 7/5, actionability 8/5

## Claude Haiku 5.5 in GitHub Copilot
- Source: GitHub Changelog
- Author: N/A
- Publish date: 2026-10-07
- URL: https://github.blog/changelog/2026-10-07-claude-haiku-5-5-in-github-copilot/

Anthropic’s Claude Haiku 5.5 is now generally available in GitHub Copilot for high-volume, low-latency scenarios such as subagents, quick edits, and terminal tasks. GitHub says early testing showed performance comparable to Claude Sonnet 5 on many coding tasks while using fewer tokens and steps, and enterprise admins can control access via model policy.

Why it matters: The main value is not simply 'another model,' but that Copilot is increasingly stratifying models by task type—using lower-cost, lower-latency models for high-frequency agent subtasks. That has direct implications for enterprise AI cost structure and default orchestration strategies, especially when agent workflows decompose one user request into many subcalls.

Key takeaways:
- GitHub explicitly positions Haiku 5.5 for subagents, terminal work, and quick edits, indicating model selection is being optimized at task granularity.
- If lightweight models approach stronger models on many coding tasks, enterprises will increasingly prefer tiered routing over a single default premium model.
